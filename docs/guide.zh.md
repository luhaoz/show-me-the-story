## 1. 安装与 API 配置

### 启动与项目

下载发布版并解压。Windows 双击后默认打开桌面窗口；Linux/macOS 启动后访问 `http://localhost:48090`。桌面窗口在任务空闲时可直接关闭；任务运行时会要求确认并先尝试取消和等待。Web 模式下关闭浏览器不等于停止后端任务。

项目名用于本地目录，小说书名用于作品展示，两者不必相同。创建项目时选择正文语言：中文或英文。项目语言决定提示词、正文和适用技能，创建后不应更换；界面语言可以独立切换。

默认使用启动时的工作目录存储数据。若需要固定位置，使用 `--data-dir` 指定已经存在的数据目录；Windows GUI 对同一数据目录实行单实例。若需浏览器回退，增加 `--web`。`PORT` 仅对 Web 模式生效，例如 PowerShell：

```powershell
$env:PORT = "48091"
.\show-me-the-story.exe --web --data-dir "D:\Novels"
```

此时访问 `http://localhost:48091`。

Windows GUI 的导出会先显示系统保存对话框，取消不会改变文件或显示成功提示。若机器未安装 WebView2 Runtime，便携发行版会调用内嵌的官方 bootstrapper；这不影响 `--web` 回退模式。

### 接通模型

在配置页填写并保存：

| 字段 | 如何填写 |
|---|---|
| API 地址 | 服务商提供的 OpenAI 兼容地址，使用 Chat Completions 接口 |
| 严格 URL 模式 | 服务商路径不应自动插入 `/v1` 时开启；仍会补 `/chat/completions` |
| 模型名称 | 填服务商的准确模型标识，不是任意显示名称 |
| API Key | 填对应服务的密钥；本地服务是否需要密钥取决于其配置 |
| 输出 token 上限 | 为一整章正文或大纲预留足够输出，同时不得超过模型支持值 |
| 上下文预算 | 按模型实际窗口配置，不要用更大数字伪造模型能力 |
| 超时 | 长章节生成需要较长时间，过短会导致中断 |

普通裸域名会补 `/v1/chat/completions`；已有路径通常补 `/chat/completions`；完整接口地址可直接使用。连接测试只验证短请求，成功不代表长篇生成的输出长度、窗口和超时也合适。测试后仍需保存配置。

API 配置在项目间共享，切换模型影响之后所有项目的调用。写作、核查、摘要、修订、规划和助理都可能产生模型费用；一次“生成章节”通常不止一次请求。

## 2. 第一次创作：推荐顺序

### 第一步：确定少量核心设定

在配置页填写故事类型、目标章节长度、写作风格和叙述视角，然后保存。先明确“谁想得到什么、遇到什么阻碍、故事的特别规则是什么”。

例如：

> 奇幻悬疑。第三人称限知，只跟随女主。女主调查失踪的姐姐。城市中的植物依靠月光生长，阳光会让它们休眠。对话简洁，线索通过行动揭示。

添加主角、关键配角和必要世界观即可，不必预先设计所有支线。角色的动机和能力边界通常比长篇外貌描述更有助于稳定写作。也可使用 AI 生成初始设定，但应检查并修改结果。

### 复用共享卡片

主界面右上角的「卡片库」是跨项目共用的侧栏。在配置页点击 API、故事参数、文风或单条人物、世界观、组织、关系上的「加入卡片库」即可保存，拖进侧栏是可选快捷方式。切换项目后点击共享卡片上的「使用」即可导入，也可以把它拖回同类型区域。

卡片库的「编辑」会显示该类型的完整内容表单，例如人物卡包含年龄、外貌、性格、背景、动机、能力和备注。编辑只改变共享卡副本，不会回写来源项目；组织成员和关系端点只能从卡片已经携带的依赖中选择。

人物和世界观主卡每次导入都会创建新 ID。组织卡会携带成员人物，关系卡会携带两端实体以及组织成员；导入时按名称复用目标项目已有的依赖，并自动补齐缺少项，然后统一重映射引用。这样不会因缺少人物或组织留下悬空关系。

故事或文风卡导入已有正式正文的项目时需要再次确认；类型、文风或视角变化后可沿用设定协调流程。卡片位于程序目录的 `shared-cards/`，不进入项目 ZIP。API 卡片中的 API Key 以明文保存，接口列表和详情不显示密钥原文，但复制整个数据目录仍会复制密钥。

### 第二步：规划第一批

进入大纲页，第一次建议规划 3–6 章。填写本批必需发生的事件、推进幅度和停止位置，而不只写题材名称。

示例：

> 女主发现姐姐留下的月光种子，进入旧温室寻找种植记录。前三章建立调查动机与搭档关系，第六章发现记录被人篡改。本批不揭开姐姐的真实去向。

长期走向可写“最终发现姐姐主动加入守夜人”，不要求本批就实现。生成后检查每章目标、人物出场、线索顺序、是否过早揭底。若出现待确认的角色建议，核对后再加入角色库。

页面出现确认大纲按钮时，确认后进入写作。生成章纲本身不会生成正文。

### 第三步：生成并审核一章

进入写作页，生成当前章，等待正文、摘要及相关检查处理完成。流式文字仍在变化或底部显示任务运行时，不要开始下一项修改。

按这个顺序检查：

1. 本章是否完成章纲目标，是否提前用了后续剧情？
2. 人物知道的信息、能力与行为是否合理？
3. 是否违反小说规则、误用知识或重复前文？
4. 对话、视角、文风是否符合期待？

有问题先修订；满意后确认。确认会推进写作位置，已确认正文还会用于设定同步。

### 第四步：继续与回顾

逐章重复生成、审核、确认。完成一小批后再追加大纲，必要时用规划复盘检查走向与伏笔。不要为了获得一部长篇而一开始填满大量未来章纲。

稳定后可开启自动确认，让系统连写到当前规划末尾。自动确认意味着放弃逐章人工审核，不代表输出已经通过作者检查。要纠错时先关闭自动确认；若任务仍在运行，等待结束或停止后再操作。

### 用同一剧本写不同版本

在项目列表找到已有项目，点击「创建正文新版本」，输入一个新项目名。新项目复制创建时的故事配置、人物与世界观等设定、批次及逐章大纲，从第一章重新写正文；原项目保持不变。旧正文、摘要、从旧正文提炼的事实、聊天和校订状态不会进入新版本。伏笔计划保留，但本版本的推进记录重新开始。当前设定如果已经吸收旧稿细节，也会被复制；需要改变这些细节时可先调整设定。

## 3. 分批规划与结尾

每批必须填写章数（1–36）和大纲梗概。长期走向、结尾用途是额外信息。当前批次梗概会参与所属章节的写作，不是只在生成大纲时使用一次。

| 操作 | 适用情况 | 影响 |
|---|---|---|
| 追加一批 | 需要更多章节 | 接在最大章号之后，已有批次保留 |
| 重新规划本批 | 最后一整批均未写、无正文、状态全为待写 | 确认后整体替换该批，可改梗概和章数 |
| 重新生成大纲 | 想在当前项目从头规划，并重写全部正文 | 确认后清空全部章节、大纲、正文及其事实、伏笔进度和校订状态；章号重新从 1 开始 |
| 编辑或修订章纲 | 事件顺序、节奏或细节需要调整 | 不会自动把已写正文变成新版本 |
| 规划复盘 | 已写若干章后检查方向 | 用已有故事上下文分析后续规划，查看日志和结果 |
| 设置结尾用途 | 本批准备收束作品 | 影响规划及收尾要求，但不自动正式完结 |

不要用删除章纲或删除章节来表达“改一下内容”。已开始写作的末批不满足整批替换条件时，应编辑相关章纲或修订正文。

「重新生成大纲」位于大纲页批次规划卡片。操作后填入新的本批梗概和章数，再生成首批章纲、重走正文流程。项目故事配置、当前人物与世界观、书名、长期方向及 Trilium 来源关联保留；从旧稿同步到这些设定中的细节也会保留，必要时先备份并手动调整设定。旧章节文件、独立章节 Markdown、导入断点、待处理配置变更和完稿校订记录会被清除。此操作不可撤销；若想保留旧稿并比较不同文章，请在项目列表先创建「正文新版本」。

要保存不同的走向与结尾方案，在大纲页填写「全书长期走向」「本批结尾用途」以及需要时的结尾方式和要求，点击「走向与结尾加入卡片库」。卡片库新增「规划」卡，可编辑名称和全部规划字段。点击卡片上的「使用」会打开大纲页并填回这些表单选项，保留当前的本批梗概和章数；此时不会修改项目里已保存的大纲或正文。确认生成新批次后，规划才进入项目。重开大纲后可用此方式快速套用另一种方案。

结尾用途可选择继续连载、全书完结、收束本书并保留续作空间。闭合式要交代主要结果；开放式也应解决当前主线，留下有意的开放问题。自定义结尾应说明哪些问题必须解答、哪些允许保留。

到预定结尾后，确认章节、检查伏笔，再手动标记作品完结。预定完结后仍追加章节，需要确认继续规划。仅仅写完当前批次不等于作品完结。

## Trilium Notes 大纲与发布

在 Trilium 创建一篇 `text` 类型的大纲笔记，复制其笔记 ID。在本应用「配置 → Trilium Notes」填写服务器 HTTP 地址和 ETAPI 令牌，保存并测试连接；令牌只在本机程序目录的 `trilium.json` 保存，不进入项目备份或配置查询结果。服务器地址需要从本机能够访问。

新项目首次规划时，在「大纲」输入笔记 ID，点击「读取大纲笔记」。笔记内容会填入本批梗概文本框；可修改梗概、选择章数，再按正常流程生成章纲。只有首批章纲成功保存后，项目才关联该来源笔记。后续批次仍按普通方式输入梗概，读取不会自动覆盖已写的章节。复制正文新版本时会保留此来源关联。

所有本版本章节都确认后，在「写作」点击「发布到 Trilium」。程序把正文按章号合并，加入章节标题，创建为原大纲笔记的**直接子笔记**；每点击一次都会创建一篇新笔记。继承的前作章节不会写入。若网络超时或返回错误，重试前先到 Trilium 检查是否已创建子笔记，以免重复发布。切换 Trilium 服务器后，需恢复原服务器配置才能继续向该大纲发布。

## 4. 审核、编辑与修订

章节大致经历：待写 → 写作中 → 待审核 → 已确认。生成失败留下的文字可能只是草稿，不应仅因为界面上出现正文就当作正式完成。

### 选择正确的修改方式

| 需求 | 推荐操作 |
|---|---|
| 错别字、确定要替换的句子 | 点击段落，使用人工编辑 |
| 一段对话或描写需要改善 | 段落 AI 修订，说明要保留的事实 |
| 整章表达或局部情节要调整 | 章节修订，写清范围与目标 |
| 小说规则写错，以后也要避免 | 补充知识设定，再按设定修订 |
| 只想改善措辞和文风 | 启用适用润色 Skill 后使用去 AI 味/润色 |
| 全书完成后的语言整理 | 完稿校订 |

普通章节修订中，当前待审核章节还可能调整后续章纲；指定其他章节的修订以该章为目标。新“按所选设定修订”始终采用指定章节流程，不自动调整其他章纲或其他正文。

修改意见要写具体目标，例如：

> 保留找到钥匙的情节，把守卫主动泄密改成女主从值班表推断。维持第三人称限知，不增加新角色。

框选正文后使用“引用到修改意见”，引用以 `> ` 开头。该方式优先只修改引用所在自然段；定位失败或返回段数不匹配时可能回退整章修订。如果要修正整章各处关联错误，请不要把修订限制在引用段落里。

正文段落选中后才显示操作栏。关联事实需要更改时会要求确认；正文版本过期时，刷新或重新选择章节，阅读新版本后再提交。确认不代表其他章节会一起修改。

## 5. 补充知识设定并纠错

### 知识应放在哪里

知识属于小说设定，不要求来自现实。配置页 → 世界观管理 → 新建条目，分类选“知识设定”。名称和描述必填，标签可写相关名词、别名。

建议一条知识表达一组紧密相关的规则，并明确适用范围、限制与例外。例如：

> 名称：月光咖啡
>
> 描述：本小说的阿拉比卡树是虚构植物。果实在月光下成熟，种子剥开即可冲泡，不需要烘焙；阳光只会使其休眠，不会杀死植株。城外普通咖啡不适用这套规则。
>
> 标签：阿拉比卡树，月光咖啡，种子，温室

不要只写“咖啡部分不对”，这不足以成为长期设定。应写出正确规则；本次具体要改哪里，可放在修改意见中。

### 发现错误后的最短流程

1. 关闭自动确认，等待任务结束，选中出错的最新章节。
2. 点击正文操作区的“补充知识设定”。
3. 填写名称、描述、可选标签。
4. 点击“保存并修订本章”。
5. 若本章存在关联事实，核对确认框，允许修正与所选设定冲突的事实。
6. 等待任务完成，检查本章相关描写和摘要，确认符合要求后继续写作。

知识先保存，修订随后开始；修订失败也不会删除已保存条目。重试时从已有条目中勾选它即可，不要重复新建。

### 先到配置页补充，再回来修订

也可以先在世界观管理中新建或编辑知识。回到写作页，选中章节，打开“补充知识设定”，勾选已保存的世界观条目，然后点击“按所选设定修订本章”。修改意见可留空，也可补充“保留原剧情，只纠正植物生长过程”。

已有地理、历史、规则等世界观条目同样可以勾选，不必复制为知识分类。知识分类额外表达“这是作者维护的规则”，正文自动同步对它的修改只形成待确认建议。

“保存”只保存设定，不修改正文；“提交世界观设定给 AI”是向助理发消息，也不等于自动修订。

### 生效范围与限制

- 勾选的条目完整加入本次修订请求，不依赖关键词命中，也不按检索预算裁掉。过长而超过模型总窗口时，请缩小所选范围或精简条目后重试。
- 后续普通写作按相关性检索，不会每次传入整个设定库。名称和标签使用正文实际会出现的名词，有助于召回。
- 规则适用于本小说，不会自动传播到其他项目。
- 修订只针对当前选中的章节；如果早期正文、其他设定或未来章纲也有矛盾，需要分别核对处理。
- 重写后沿用摘要、事实和设定同步流程；留意待同步提示和待确认建议。AI 可能漏改，最终以你阅读正文为准。
- 如果不同条目互相矛盾，先明确例外和适用范围，或编辑冲突条目，再要求 AI 修订。

<a id="consistency"></a>
## 6. 事实、设定与伏笔如何配合

| 信息 | 含义 | 作者如何使用 |
|---|---|---|
| 世界观/角色/组织/关系 | 世界规则和实体资料 | 维护创作依据 |
| 知识设定 | 需要明确遵循的小说知识或规则 | 补充和纠正模型理解，可以虚构 |
| 正文事实 | 从正文提取的已发生事件与细节 | 核对故事连续性和来源，不是现实真理证明 |
| 摘要 | 章节主要进展 | 快速回顾，留意修订后是否更新 |
| 伏笔 | 计划埋设、推进和回收的线索 | 检查预期回收位置与当前状态 |

写作页正文卡片内的事实/设定面板默认折叠，摘要常驻。事实标记可展开并跳转到来源段落；来源变化后需要重新核对。AI 提取可能遗漏，未被标记不等于没有影响。

已确认正文可自动推动设定演变。与作者设定冲突或证据不足时，会展示建议供采纳或忽略。知识设定的变化需要作者批准，不会因为 AI 称其为“剧情演变”就自动覆盖。

同步失败时，先查看日志，再使用知识同步重试入口。正文已保存与知识同步已完成是两件事；任务结束后仍可能有待同步项。

伏笔可由 AI 建议，也可手动创建。检查描述、埋设与回收章节，持续查看已埋设、推进中、已回收或已放弃状态。完结前处理不再使用的伏笔，避免模型把它们当成仍需展开的支线。

长篇上下文有预算：近期摘要、远期分层摘要、相关事实/设定及有限未来章纲共同提供背景。模型不会在每次请求中重新读完整本书，维护清晰设定比无限堆积描述更有效。

远期摘要生成失败时会记录警告，暂用本地截断摘要，下次使用时重试；恢复后会更新相关上级摘要。停止任务不会保存本次尚未提交的摘要检查点。

<a id="import"></a>
## 7. 导入作品与继续创作

### 已有文本接着写

1. 创建空项目，选择与原文匹配的项目语言。
2. 到大纲页选择“导入已有内容”，粘贴文本。
3. 查看本地切章预览；若章节标题识别不符合预期，先整理原文标题再预览。
4. 开始导入，等待元信息和逐章分析完成。
5. 检查导入章节、摘要、角色与世界观。中断后使用继续分析/恢复导入入口，不必重复导入全文。
6. 填写新一批梗概和章数，规划接下来的故事，再开始写作。

导入章节作为已确认历史使用，不需要重新逐章生成。导入是让系统接续作品，不是从 TXT 恢复完整项目：聊天、技能选择和所有人工设定不一定能从正文重建。

### 已完结作品续作

如果尚未在完稿校订中改动正文，可以按页面允许的恢复连载流程继续原项目。校订中一旦修改正文，原项目不再回到普通写作流程。

此时在完稿校订页填写新项目名，使用“创建续写项目”。新项目继承冻结的设定、事实、章纲、摘要与伏笔快照，不复制校订后的正文。章号接续前作，新项目进度只统计新写章节。

“前作继承”的伏笔是独立快照，修改新项目不会同步回前作。若你在校订中改变了重要剧情或规则，应核对并补充新项目继承的设定与摘要，不能假定校订正文已经重新提取为写作知识。

<a id="completion"></a>
## 8. 完稿、校订与导出

1. 确认所有计划章节，检查主线结果和伏笔，正式标记完结。
2. 进入完稿校订页，先下载未校订全文和全部大纲，确认备份后进入。
3. 如需改善语言，填写文风偏好并运行自动校订全文。
4. 生成交互式报告，逐项查看逻辑、结构、人物和伏笔问题。
5. 点击章节/段落定位原文；人工处理后标记已处理，不准备采纳的标记忽略。
6. 抽查自动校订的前后差异，必要时按章撤销，最后导出全文、大纲和报告。

自动校订以错字、病句、重复、对话和文风为范围，不负责重构剧情；报告用来列出需要作者判断的问题。两者作用不同，可按需要分别运行。

校订按章处理，失败章节可重试；取消不撤回此前已经保存的章节。逐章撤销是校订流程的能力，不应当作所有写作修改的通用撤销功能。

TXT、Markdown 大纲和报告适合阅读与交付，不能替代完整项目备份。

<a id="skills"></a>
## 9. 技能与 AI 助理

### 技能

新建项目默认启用匹配项目语言的内置“成人小说写作（固定 4 级）”Skill，其他 Skill 默认关闭；已有项目不会因升级被自动启用。成人 Skill 作用于大纲、章节生成、修订和润色，只允许明确为成年且明确合意的虚构关系，并可随时在技能页关闭。模型服务商仍可能按自身内容政策限制输出。

按需要启用少量匹配项目语言的其他技能。作用域决定技能用于生成、润色、大纲还是校订；启用不代表每个请求都使用，实际生效项查看日志。中文成人 Skill 内置直白、文学和现代网文三种语域的词汇与用法参考，同时约束重复用词、动作连续性、人物视角、场景过渡和事后余波；词库不是要求逐项使用的清单。

技能可通过粘贴 Markdown、上传 Markdown、ZIP 或选择文件夹安装。用户技能存放在全局 `skills/<id>/`，各项目分别启用。标准包包含 `skill.json` 和 `SKILL.md`，支持安全的文本资源，不执行其中的脚本或二进制。

非内置技能可运行 AI 校验；未校验仍可启用，判定需优化或不通过时不能启用。AI 优化会生成副本并复检。技能内容变化后需要重新校验。

项目特有的“魔法必须消耗记忆”等规则放在世界观知识设定；可跨作品复用的写作方法适合 Skill。避免同时启用要求互相冲突的技能。

### 助理

核心流程优先使用页面按钮。助理适合查询、批量起草设定、解释问题，以及明确的自然语言修改：

> 查看第 4 章与月光植物有关的设定，指出冲突，先不要修改。

> 修订第 4 章：依据“月光咖啡”条目改正采摘过程，保留调查结果，不修改其他章节。

> 为最后一批提出节奏调整建议，保持章数不变。

“修改章节”与“删除章节”含义不同；涉及删除时核对助理复述的范围。助理启动异步任务后，先查看任务状态和日志，完成后再提出下一项写入请求。完稿校订、导入和图谱操作使用对应页面更清楚。

<a id="data"></a>
## 10. 保存、备份与迁移

常见目录：

```text
<数据目录>/
├── api.json                 # 全局连接配置，可能包含密钥
├── shared-cards/            # 全局共享卡片；API 卡片可能包含明文 API Key
├── skills/                  # 安装的用户技能
└── storys/<项目名>/
    ├── config.json          # 项目语言、故事配置、提示词、技能开关
    ├── progress.json        # 章纲、状态、摘要、事实、伏笔等
    ├── chapters/            # NNNNNN.json：正文事实源
    ├── settings.json       # 角色、世界观、组织、关系和来源信息
    ├── sessions/            # 助理会话
    ├── import.json          # 导入检查点，按需创建
    └── postprocess.json     # 完稿校订状态，按需创建
```

程序也可能生成章节 Markdown 副本等辅助文件。直接编辑这些副本不会更新应用里的正文；使用页面编辑正文。

正文与进度通过临时回滚日志 `progress.json.rollback` 一起保存。写入中途失败会恢复旧文件；程序异常退出后，重新打开项目会先恢复未提交的保存。恢复日志保留期间不要删除它或使用旧版程序打开项目。恢复失败时，先关闭程序并复制整个项目目录，再处理权限、磁盘空间或同步软件问题后重试。章节缺失或损坏会阻止项目打开，并指出章号和路径；无法修复时从完整备份恢复。该机制不提供任意历史版本，且同一项目只能由一个程序写入。

修改章纲或确认伏笔后，若有伏笔需要检查，会显示一致性检查任务。检查期间不能启动其他 AI 任务或切换项目；可以使用停止任务按钮取消。检查失败不撤销已经保存的章纲或伏笔，可稍后点击一致性检查重试。

可靠备份步骤：停止 AI 任务 → 等待保存 → 关闭程序 → 复制整个数据目录到带日期的备份位置。迁移到新电脑后，让程序使用复制后的目录。仅备份单个项目时，还需另行保存它依赖的用户 Skill；不要把 API Key 随作品公开分享。

也可直接使用项目列表的备份与恢复：

1. 等待 AI 任务结束，返回项目列表，点击对应项目的「备份 ZIP」。保存下载文件。
2. 需要恢复时，在「从项目备份恢复」选择 ZIP，并填写一个尚不存在的新项目名。
3. 点击「恢复为新项目」。成功后从列表打开新项目，核对正文、设定和校订状态；原项目保持不变。

ZIP 包含项目目录内的正文、进度、配置、设定、会话、导入及校订状态，不包含数据目录的 `api.json` 或 `skills/`。备份和恢复期间会串行处理项目写请求；恢复会检查 ZIP 路径、文件大小、JSON、v4 格式和章节完整性，失败不会发布半成品项目。限制为 ZIP 256 MiB、解压后 512 MiB、单文件 64 MiB、20000 个条目；更大的项目可在关闭程序后复制目录。ZIP 是完整项目快照，TXT 导入不能替代它。

当前程序仅加载 v4。旧版本项目会被标识并提示合适的程序版本，不自动迁移。格式版本是存储协议，不是可以手动改一下就升级的开关。

<a id="troubleshooting"></a>
## 11. 常见问题

| 现象 | 建议处理 |
|---|---|
| 生成/保存按钮不可用 | 查看是否有 AI 任务运行，以及是否满足章纲确认、当前章节状态或完结条件 |
| 浏览器刷新后看似丢失进度 | 等待服务器状态恢复，确认选择的项目和启动数据目录；不要立即新建同名项目。断线重连或运行状态轮询会校准任务状态，后端已结束时自动解除运行提示 |
| API 测试失败 | 核对地址、严格模式、模型标识、密钥与服务状态 |
| 401/403/404 | 优先检查凭据、权限和端点路径，反复重试通常无效 |
| 长章节失败但连接测试成功 | 检查输出上限、上下文窗口、超时及服务的流式兼容性 |
| 上下文超限 | 使用真实窗口；缩短本次输入或减少所选知识；更换足够窗口的模型后重新配置 |
| 流式输出中断 | 查看日志；半截响应不能当作完整成功结果。停止后检查章节状态再重试 |
| 写作冲突提示 | 查看冲突原因，按页面选择调整章纲、重试或保留草稿进入审核；强行继续前阅读正文 |
| 知识已保存但正文没变化 | 保存不等于修订；选中目标章，勾选条目，再提交按设定修订 |
| 修订后仍有知识错误 | 核对所选条目是否清楚、是否互相冲突、是否被引用限定到局部；说明具体遗漏再修订 |
| 事实版本冲突/409 | 重新加载章节，核对最新正文，再次确认影响，不要重复提交旧确认 |
| 知识同步失败 | 保留正文，查看错误并重试同步；检查待确认设定建议 |
| 存储错误弹窗 | 先处理权限、磁盘空间或文件占用；不要把任务结束或普通提示当作保存成功 |
| 不能重建末批 | 只有最后一整批全部待写且无正文时允许；已写内容请用修订 |
| 校订后不能恢复连载 | 在校订页创建续写项目，并核对继承资料 |
| 找不到旧项目 | 核对数据目录与格式版本，使用对应旧版程序，不手改格式号 |

任务日志显示的是各子步骤，不只是模型正文。问题反复出现时，记录任务类型、最后错误、模型配置（去除密钥）与复现步骤再反馈。
